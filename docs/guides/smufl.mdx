多年来，alphaTab 使用 SmuFL 字体 Bravura 来渲染音乐记谱符号。但从历史上看，许多视觉方面，如间距、填充和其他布局都是源自 alphaTab 根源的自定义开发。
虽然乐谱通常看起来不错，但 SmuFL 规范的各个方面并未遵循，导致根据该规范的显示"不正确"。

在 1.7.0 版本中，我们清理了多年来积累的音乐记谱布局自定义，使内容更接近规范。
这一更改不仅使 alphaTab 的外观和感觉更接近其他音乐记谱软件的预期，还允许使用自定义的 SmuFL 兼容字体。

SMuFL 字体由两个主要部分组成：

1. 字体本身，保存字形的绘图和文本布局信息
2. 一个单独的 metadata.json，保存 SMuFL 规范特定的尺寸使用细节。

要激活自定义字体，必须将这两项提供给 alphaTab。以下示例展示了使用不同 SMuFL 字体的相同乐谱：

```ts
import * as alphaTab from "@coderline/alphatab";
const settings = new alphaTab.Settings();

// 1. 告诉 alphatab 在哪里找到字体
settings.core.smuflFontSources = new Map<alphaTab.FontFileFormat, string>([
    [alphaTab.FontFileFormat.OpenType, 'Petaluma.otf']
])

// 2. 填充包含所有尺寸和间距信息的元数据
const petalumaMetadata = await loadJsonViaAjax('petaluma_metadata.json');
settings.display.resources.engravingSettings.fillFromSmufl(petalumaMetadata);

// 3. 像往常一样初始化 alphaTab
const api = new alphaTab.AlphaTabApi(document.querySelector('#alphatab'), settings);
```

## 限制

### 不支持动态字体更改

alphaTab 无法动态更改一个实例中使用的字体。因此更改 `smuflFontSources` 不会对重新渲染产生任何效果。
在这种情况下，销毁当前的 `AlphaTabApi` 实例并创建一个新实例。

### 不完整的 SMuFL 字体

我们注意到，除了 Bravura 之外，没有多少字体提供 alphaTab 使用的所有符号。alphaTab 没有回退机制
在这种情况下使用其他字形。此外，某些字体对不支持的字形有占位符符号。

alphaTab 尝试使用 `metadata.json` 中的信息警告缺失的字形。

调用 `fillFromSmufl` 时检查控制台警告。
