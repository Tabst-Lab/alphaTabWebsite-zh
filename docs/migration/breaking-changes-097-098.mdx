在 0.9.8 版本中，alphaTab 从 C# 代码库迁移到了 TypeScript 代码库。在为 1.0.0 版本做准备的过程中，进行了大量的清理工作，并对 API 的许多方面进行了审查和更改。此次（再次）破坏性变更的目标是提供一个面向未来的 API 接口，使其能够在多个版本中保持稳定，无需再次进行大规模重构。

虽然此版本带来了许多新优势，但本指南仅聚焦于破坏性变更以及如何升级您的应用程序。

## Web 版本

对于 Web 版本，我们尽可能保持了兼容性，同时不放弃我们想要引入的更改。

### 快速迁移

在大多数情况下，开发者无需使用 alphaTab 暴露的所有类，而是可以坚持使用主 API 接口并仅访问属性。此版本的属性名称没有变化。主要变更可以总结如下：

* 主 API 类从 `alphaTab.AlphaTabApi` 移动到了 `alphaTab.alphaTabApi`
* 枚举现在有了简洁的名称，如 `alphaTab.LayoutMode`
* 接口已被移除
* `AlphaTexExporter` 被完全移除
* 检查已使用的事件名称是否有变更
* 检查隐藏乐谱元素的新设置
* 如果您使用了 API 对象事件，请使用新的 `on/off` 事件订阅方式

如果您直接使用了 `alphaTab` 模块中的各种类，可以在下方找到完整的变更列表以供迁移参考。

### 错误处理

`error` 事件以前包含 2 个参数：一个用于错误类型，另一个用于错误详情。
现在错误类型已移至错误详情本身。内部错误扩展了默认的 `Error` 类型，但由于序列化，这些信息可能会丢失。`error.type` 属性包含 `alphaTab.AlphaTabErrorType` 中的一个值，用于指定引发的错误类型。

**变更前**

```js
api.addError(function(type, error) {
    if(type === 'import') {
        alert('输入文件格式无效：' + error.message);
    }
})
```

**变更后**

```js
api.error.on(function(error) {
    if(error.type === alphaTab.AlphaTabErrorType.Format) {
        alert('输入文件格式无效：' + error.message);
    }
})
```

## .net 版本

对于 .net 版本，代码变更比 Web 版本大得多。.net 版本现在通过 TypeScript 到 C# 编译器从 Web 版本自动生成。由于 TypeScript 是 JavaScript 的超集，可用的数据类型减少了。因此，alphaTab 现在大量基于 double 值，而早期可能使用了 float 和 int 值。这可能导致更高的内存消耗和重大的破坏性变更。

### 新的包和命名空间

第一个变更是关于新的包和命名空间。alphaTab 的 .net 版本被重组为两个独立的 NuGet 包：

1. **AlphaTab** 是一个面向 .net standard 2.0 的包，仅包含主 alphaTab 模块，不含 UI 特定组件
2. **AlphaTab.Windows** 是一个面向 .net core 3.1 的包，包含 WinForms 和 WPF 特定的 UI 组件。

由于 .net Framework 4.x 已弃用，而 .net core 3.x 及后来的 .net 5 是未来方向。如果您确实需要 .net 4.x 包，请随时联系我们。

### 新的事件系统

与 Web 版本一样，.net 版本也受到事件系统重构的影响。.net 版本不再使用 C# 内置的事件系统。
通过事件对象的 `.On(handler)` 方法订阅事件，通过 `.Off(handler)` 方法取消订阅。

| 变更前                        |   变更后                               |
|-------------------------------|---------------------------------------|
| `PlayedBeatChanged += -=`     |  `PlayedBeatChanged.On/Off()`         |
| `BeatMouseDown += -=`         |  `BeatMouseDown.On/Off()`             |
| `BeatMouseMove += -=`         |  `BeatMouseMove.On/Off()`             |
| `BeatMouseUp += -=`           |  `BeatMouseUp.On/Off()`               |
| `Loaded += -=`                |  `ScoreLoaded.On/Off()`               |
| `Resize += -=`                |  `Resize.On/Off()`                    |
| `RenderStarted += -=`         |  `RenderStarted.On/Off()`             |
| `RenderFinished += -=`        |  `RenderFinished.On/Off()`            |
| `PostRenderFinished += -=`    |  `PostRenderFinished.On/Off()`        |
| `Error += -=`                 |  `Error.On/Off()`                     |
| `ReadyForPlayback += -=`      |  `PlayerReady.On/Off()`               |
| `PlayerFinished += -=`        |  `PlayerFinished.On/Off()`            |
| `SoundFontLoaded += -=`       |  `SoundFontLoaded.On/Off()`           |
| `MidiLoaded += -=`            |  `MidiFileLoade.On/Off()`             |
| `PlayerStateChanged += -=`    |  `PlayerStateChanged.On/Off()`        |
| `PlayerPositionChanged += -=` |  `PlayerPositionChanged.On/Off()`     |
| `SoundFontLoad += -=`         |  `SoundFontLoad.On/Off()`             |

### 基于 Double 的类型系统

在许多您可能期望使用 `int` 值的地方，您现在会发现 `double` 值。这并不一定意味着应该填写或支持小数值，而是因为我们从 TypeScript 代码库中无法确定属性、参数或变量是否为整数。我们计划在未来改进类型情况，但目前建议开发者在向 alphaTab 传递值时要小心，并报告未处理的潜在错误。

内部 alphaTab 会尝试在不需要的地方截断值的小数部分，但可能会有遗漏的地方。

### 错误处理

新的错误报告系统完全基于 `Exceptions`，您应该使用相应的异常类型来确定错误类型。对于更高级别的分类，也可以检查 `AlphaTabError.Type` 属性。以前用于标识类别的字符串值已被移除。

## 隐藏元素的新选项

此版本还更改了一些用于隐藏/显示单个乐谱元素的选项。

以前 `NotationSettings` 有以下设置：

- `hideInfo` - 隐藏常规歌曲信息
- `hideTuning` - 隐藏吉他调弦
- `hideTrackNames` - 隐藏连谱号中的音轨名称
- `hideChordDiagrams` - 隐藏和弦图
- `showParenthesisForTiedBends` - 对连音推弦的音符头显示括号
- `showTabNoteOnTiedBends` - 在连音推弦上显示制表符音符数字
- `showZeroOnDiveWhammy` - 在俯冲摇把效果上显示数字 0

所有这些设置都已统一到新的设置 [`NotationSettings.elements`](/docs/reference/settings/notation/elements) 下。
请查看相关文档了解如何显示或隐藏这些元素。
