## 1.4.0

时光飞逝，距离 1.3.0 发布已经快一年了。因此，早就该有一个正式的 alphaTab 版本了。

v1.4.0 再次带来了许多新功能，主要围绕扩展文件格式支持。

### 音乐记谱

此版本的 alphaTab 添加了一系列新的音乐记谱功能和渲染调整。
以下列表（大致）按添加功能的视觉影响排序。

#### 渲染：填充和边距的更改
https://github.com/CoderLine/alphaTab/pull/1524

在 v1.3 之前，alphaTab 对其定义的填充和边距相当慷慨，并且没有调整这些大小的可能性。
这样，即使是小型乐谱，alphaTab 也需要相当多的屏幕空间。通过此功能，我们为影响系统和谱表放置的所有通用间距引入了可配置的填充和边距。同时，我们将填充减少到更合理的默认值，从而实现更紧凑的显示。

<img src="/img/release/v14/concise.png" />

有一系列新设置允许配置填充。

#### 记谱：斜线记谱
https://github.com/CoderLine/alphaTab/pull/1511

alphaTab 现在可以额外显示斜线记谱谱表。在 Guitar Pro 6-8 文件中，配置的谱表会被遵循，
在 alphaTex 中，可以使用新的 `slash` 谱表选项。或者可以通过数据模型上的 `score.track[].staves[].showSlash` 启用谱表。

<AlphaTab tex="true">{`
\bracketextendmode nobrackets
.
\staff {score tabs slash}
1.6.4 1.6.8 1.6.8 1.6.2 |
1.6.4 {tu 3} 1.6.4 {tu 3} 1.6.4 {tu 3} r.2 |
5.5.1 | r.1
`}</AlphaTab>

#### 记谱：添加简谱（Jianpu）
https://github.com/CoderLine/alphaTab/pull/1628

alphaTab 现在可以额外显示简谱谱表（又称 Jianpu）。在 Guitar Pro 6-8 文件中，配置的谱表会被遵循，
在 alphaTex 中，可以使用新的 `numbered` 谱表选项。或者可以通过数据模型上的 `score.track[].staves[].showNumbered` 启用谱表。

<AlphaTab tex="true">{`
\bracketextendmode nobrackets
.
\staff {score tabs numbered}
1.6.4 2.6.8 3.6.8 4.6.2 |
5.6.4 {tu 3} 10.6.4 {tu 3} 12.6.4 {tu 3} r.2 |
5.5.1 | r.1
`}</AlphaTab>

#### 记谱：系统括号和花括号
https://github.com/CoderLine/alphaTab/pull/1730

在 alphaTab 1.3 之前，总是有一个矩形括号跨过一个音轨的谱表绘制。在 alphaTab 1.4 中，显示现在可以在多种模式下配置。参见[括号与花括号](/docs/showcase/general#brackets-and-braces)了解更多详情。

<AlphaTab tex="true" tracks="all">{`
\bracketextendmode GroupStaves
.
\track 
    \staff {score}
    C4 D4 E4 F4
    \staff {score}
    \clef f4 C3 D3 E3 F3
\track 
    \staff { score tabs }
    0.3.4 2.3.4 5.3.4 7.3.4 
`}</AlphaTab>

### 播放器

#### 播放器：SoundFont3 支持（实验性）
https://github.com/CoderLine/alphaTab/pull/1807

alphaTab 1.4.0 添加了对 SoundFont3 文件的实验性支持。在 SF3 文件中，音频样本编码为 OGG Vorbis，这允许在通过网络传输音色库时占用更小的空间。这允许使用更高质量的音色，而不会直接增加传输给客户端的文件大小。

音频样本的解码需要额外的 CPU 时间，这可能会影响用户。只有歌曲播放所需的样本才会被解码以减少负载。

alphaTab 现在附带了一个 SF3 版本的 Sonivox 音色库，但默认情况下仍启用 SF2 文件的使用（如果已嵌入）。

我们尚未彻底测试许多文件的解码以及解码时间的影响。因此，该支持仍被认为是实验性的。

#### 播放器：实时更改移调音高
https://github.com/CoderLine/alphaTab/pull/1642

[`changeTrackTranspositionPitch`](/docs/reference/api/changetracktranspositionpitch) 和 [`setChannelTranspositionPitch`](/docs/reference/types/synth/ialphasynth#setchanneltranspositionpitch) API 允许在播放歌曲时实时更改各个音轨（或 MIDI 通道）的移调音高。

* 自定义三连音
* 摇把类型和样式
* 推弦类型和样式
* 节拍八度
* 连音
* 乐器自动化
* 延长记号
* 自定义符杠模式和符干方向。
* 显示弦号
* 不可见音符
* 连音线
* 常用拍号
* 调号类型
* 双小节线
* 八度
* 小节缩放（用于系统布局）
* 固定小节宽度（用于系统布局）
* 反复记号

### 改进与错误修复

#### API：JSON 设置的 TypeScript 定义
https://github.com/CoderLine/alphaTab/pull/1562

alphaTab 现在为设置的 JSON 风格提供 TypeScript 类型定义，以便在使用 `settings.fillFromJson`、`new AlphaTabApi()` 等 API 时获得更好的类型安全和编码辅助。

#### 文档：文件格式兼容性
我们在记录当前支持的文件格式和功能方面投入了大量精力。
对于每种格式，我们现在都尝试列出该格式提供的功能以及 alphaTab 从中理解了什么。

前往[格式文档](/docs/category/formats)了解更多关于功能覆盖范围的信息。

#### 渲染：乐谱的中央缩放
https://github.com/CoderLine/alphaTab/pull/1772

在此版本之前，alphaTab 在绘制项目的不同位置处理乐谱的缩放。
如果某些填充或大小的缩放比例应用错误，这很容易出错。
为了消除这个问题，我们将缩放渲染移到了绘图层（`ICanvas`）。这样
我们就不再需要在整个代码库中处理缩放级别。

这应该会带来更一致的缩放体验和更少的重叠。

#### 渲染：速度自动化渲染（标签、定位和缩放）
https://github.com/CoderLine/alphaTab/pull/1906

在此版本中，我们改进了速度信息的渲染。除了再次添加渲染速度标签外，
我们还改进了节拍上方速度变化的放置。这对`支持一个小节内的多个速度变化`至关重要。

##### 打包器：Vite & WebPack 集成的 Node20+ 兼容性
https://github.com/CoderLine/alphaTab/pull/1579

随着 Node20 的出现，我们在复制文件方面进行了一些更改，必须适应 Vite 和 WebPack 插件。这可能导致错误的文件复制步骤。

##### 音频：防止音频削波噪声
https://github.com/CoderLine/alphaTab/pull/1607
https://github.com/CoderLine/alphaTab/pull/1609

我们改进了各种可能导致此削波问题的部分。

#### 渲染：确保换行时效果带的正确大小
https://github.com/CoderLine/alphaTab/pull/1621
https://github.com/CoderLine/alphaTab/pull/1641

此问题已修复。
