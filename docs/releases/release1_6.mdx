## 1.6.0

alphaTab 的又一次全新发布，主要聚焦于播放器的两个新功能。😎🎉
想要将 alphaTab 与 YouTube 视频或音频录音集成？现在你可以了。

### 播放器

#### 外部光标 API

https://github.com/CoderLine/alphaTab/issues/1961

<video src='/img/landing/audio.mp4' autoPlay={true} muted={true} loop={true} controls={false} style={{maxWidth: "100%"}} />

这是此版本的亮点功能。它涵盖了将 alphaTab 显示的乐谱
与外部媒体（如音频伴奏和视频）同步所需的所有扩展。

此功能的基础是一个"同步点"系统，它配置了外部媒体与 alphaTab 通过合成器精确播放之间的任何时间差异。配置好此信息后，有两个选项：

1. 传入一个支持的音频文件，让 alphaTab 为你处理媒体控制。
2. 提供一个自定义处理程序，接收来自 alphaTab 的调用，并向 alphaTab 提供与外部媒体同步所需的任何信息。


对于 1.，我们还添加了对 Guitar Pro 8 伴奏音轨的支持。alphaTab 可以使用嵌入到 Guitar Pro 8 文件中的音频伴奏音轨，包括同步细节。
这样，alphaTab 可以播放集成的音频，而不是使用合成器，为你的乐谱带来惊人的声音体验。


对于 2.，你可以自己控制使用什么外部媒体系统，而不是使用合成音频。通过数据模型提供的同步信息，你可以向 alphaTab 提供自定义逻辑，告诉它媒体的状态，例如它是否正在播放以及当前时间。
通过此系统，你可以与 YouTube iFrame API 等播放器集成，我们甚至为此提供了一个小示例。


使用你自己的视频或音频录音或使用高质量声音合成器生成的音轨来丰富你的 alphaTab 乐谱。

#### 音频导出 API

此版本中的第二个大功能是获取 alphaTab 使用其内部播放器合成的原始音频数据的可能性，允许你构建"导出音频"等新功能，或将音频输入到其他媒体系统中。

不幸的是，视觉上没有太多可展示的，但要了解更多关于此功能的信息，请前往[相关功能指南](/docs/guides/audio-export.mdx)。

通过新的异步流式 API，原始音频可用，你可以拉取单个音频块进行自定义处理。

构建你自己的音频管道：

* 通过将样本发送到音频编解码器（MP3、OGG Vorbis，无论你有什么库）来压缩音频，同时保持较低的内存使用量。
* 将音频发送到任何自定义目标。让你的用户与他人分享歌曲的部分内容（通过 WebRTC 等 Web 平台功能实时进行），或者将音频发送到你的服务器。
* 将 alphaTab 的音频样本与其他系统组合，例如将其与其他音频混合，通过进一步的音频处理器发送，或将单独音轨的播放拆分到单独的输出设备。

通过新的音频导出 API，你可以按需获取音频。

### 渲染

#### Web：允许自定义 Web 字体源

https://github.com/CoderLine/alphaTab/issues/2113
https://github.com/CoderLine/alphaTab/discussions/2112
https://github.com/CoderLine/alphaTab/pull/2114

从历史上看，alphaTab 期望 Bravura 字体放置在一个可配置的 URL 上，但文件名和格式是固定的。
[`fontDirectory`](/docs/reference/settings/core/fontdirectory.mdx) 允许更改一些基本 URL 和路径，但仅此而已。

通过此新功能，开发者现在可以更精确地指定应使用什么格式和 URL 来加载 Web 字体。

这也允许在更隔离的环境中更轻松地使用，其中字体必须嵌入到应用本身中。
通过使用数据或 blob URL，字体可以通过自定义方式加载，然后传递给 alphaTab 使用。

[smuflFontSources](/docs/reference/settings/core/smuflfontsources/) 选项也是允许使用替代 [SMuFL](https://www.smufl.org/) 兼容字体的第一个准备。

完整支持将随 [#1949](https://github.com/CoderLine/alphaTab/issues/1949) 一起到来，届时我们将添加读取所需大小、填充和其他元数据的支持，以真正正确对齐符号。

### 改进与错误修复

#### 播放器：确保合成器在到达末尾时停止声音

https://github.com/CoderLine/alphaTab/pull/2080
https://github.com/CoderLine/alphaTab/issues/2076
https://github.com/CoderLine/alphaTab/issues/1803

合成器中存在一个问题，导致它"继续播放"，即使它应该停止。
在内部，可能会发生声音保持活动并产生音频样本（通常只是静音）的情况。

此修复确保 alphaTab 额外请求停止这些声音，以便播放完全停止。

在预备拍的情况下，这可能导致实际音频开始前的延迟。
在只应播放有限时间范围的情况下，这会导致播放器继续播放。

#### Kotlin：Android 平台 OutOfMemory 崩溃

https://github.com/CoderLine/alphaTab/pull/2085
https://github.com/CoderLine/alphaTab/issues/1959

我们在 Kotlin 平台上有一个有问题的列表实现，主要在我们用于合成器区域的 `Queue` 数据结构中引起问题。

Java 平台上的 `java.util.ArrayList.subList()` 方法的行为与我们预期的不同。它没有给我们一个副本，而是创建了一个与主列表共享内部存储的 `java.util.ArrayList$SubList`。如果你然后对两个列表分别进行修改，列表可能会损坏。

文档提到：

> 返回此列表一部分的**视图**...如果支持列表（即此列表）以除通过返回列表以外的任何方式进行结构修改，则此方法返回的列表的语义将变为未定义。

我们现在通过在需要的地方制作 ArrayList 的适当副本来避免此问题。

#### musicxml：允许空 direction-type

https://github.com/CoderLine/alphaTab/pull/2111
https://github.com/CoderLine/alphaTab/issues/2102

如果未遵循 MusicXML 规范，这可能导致 alphaTab 的 MusicXML 导入器产生错误的预期。
在这种情况下，MuseScore 有一个 bug，它没有写入必需的子标签。因此，我们改进了 MusicXML 导入器
以更优雅地处理此类情况。我们现在尝试始终检查某些标签和属性是否确实存在，并尝试缓解
如果未遵循规范可能产生的任何问题。

#### API：动态设置更改

https://github.com/CoderLine/alphaTab/pull/2098

在为网站构建新游乐场时，我们注意到某些动态设置更改未产生预期的行为。
通过这些更改，我们现在允许更优雅地动态切换所有设置。

例如，从 HTML5 切换到 SVG 再切换回来可能会导致 alphaTab 停止工作的问题。

#### Vue：尽可能解包 Vue 代理

https://github.com/CoderLine/alphaTab/issues/2097
https://github.com/CoderLine/alphaTab/pull/2132

Vue 的响应式系统将所有对象包装成代理。在这样的设置中使用 alphaTab 时，
你总是需要调用 [`toRaw`](https://vuejs.org/api/reactivity-advanced#toraw) 以避免代理
被传递到会导致问题的区域。

通过这些更改，我们尝试在需要的地方自动解包 Vue 的代理，避免将对象发送到工作者时出现问题。

在 Web 平台上，如果需要为另一个框架使用自定义机制，可以替换 `alphaTab.Environment.prepareForPostMessage`。
例如，对于 Solidjs，需要调用 `unwrap`。

#### 平台：Electron 和 Obsidian 兼容性

https://github.com/CoderLine/alphaTab/discussions/1933
https://github.com/CoderLine/alphaTab/issues/2151
https://github.com/CoderLine/alphaTab/pull/2152

Electron 向渲染器进程（浏览器）注入了一些全局变量，这些变量通常只在 Node.js 中可用。
因此，alphaTab 错误地将环境检测为 Node.js，并阻止了 `AlphaTabApi` 的使用。

通过此处完成的改进，我们现在更好地检测是否在浏览器窗口中运行，允许在 Electron 应用中更轻松地使用。
